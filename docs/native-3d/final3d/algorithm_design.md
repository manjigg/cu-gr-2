# 三维拓扑候选与跨线网联合选择

## 固定目标与物理约束

双裸片顶点由裸片号、金属层和局部 GCell 坐标组成。边保留 Wire（金属导线）、Via（同裸片层间通孔）和 HBT（混合键合端点）三种身份。同一 HBT 的不同层对共用物理站点资源。Pin（端点）的接入候选来自原始终端组。跨裸片切分端口继续负责映射两个局部网。

对完整候选树 \(T\)，固定代价为 \(c(T)=w_L L_\mu(T)+w_V V(T)+w_H H(T)+\sum_r \phi_r(D_r(T))\)。需求 \(D_r\) 包含导线、通孔、通孔附加接入和可选的 HBT 接入占用。资源价格 \(\phi_r\) 常用项为 \(w_rD_r/(1+C_r)\)。导线短路面积代理启用时，按导线物理长度、宽度、静态容量及本候选需求加计。正式协议沿用权重 1、1、4、1 和 metal7/metal7。RoutingGraph::extraPrice 的动态价格仅引导搜索。RouteResourceSummary 保存固定代价，组间固定目标按线网可加。

组内替换累加导线、通孔、HBT 接入等全部需求。站点独占、最小间距、层对、固定所有权和终端树连通各自验证。Budgeted Mode（预算模式）比较 \((\max(0,H_\mathrm{outside}+H_\mathrm{group}-B),F)\)。Joint Mode（联合模式）比较固定目标 \(F\)。两种模式都容许未连接线网首次合法布线。Baseline Mode（基准模式）保留原有算法及每网 HBT 非增长逻辑。

## 候选生成与阶段预算

Stage 1 的 initialCandidates 沿用 FLUTE 二维骨架以及原有的模式、迷宫和跨裸片 Prim 初解。Stage 2 先调用 V3 optimizeConflicts。ExchangeStage 交替处理一根线网的候选生成和一个待处理联合任务。新路径父期限覆盖 master_seconds 与 stage_seconds 之和。档案、再搜索、组合检查、提交和证据写出均受其约束。子任务取单网预算与父期限的较早值。已执行的事务完成验证和发布，统计协作式超时的实际超限。Stage 3 继续使用原有并行迷宫机制和内存回退。

refineTopology 与 enumerateFast 接收显式 ResourceReadView（只读资源视图）。单网视图扣除当前线网的旧需求。三维拓扑由局部割边和分量重连构成。Merge（合并）减少 HBT。Relocation（迁移）保持数量并禁止复用本次切除的站点。Augmentation（增补）增加 HBT，通过保护真实终端和固定站点的树叶消除检查新 HBT 参与连接。Steiner Migration（分叉点迁移）和 Edge Reconnection（局部换边）复用 V3 操作。可选的操作轮转共用尝试上限。局部路径及预算仍限制生成范围。

基准 PatternSearch 的原 CUGR 二维拥塞绕行读取可变 GridGraph。协调模式在只读视图中使用同一三维图的模式路径、HBT 路径和已有拓扑操作。evaluateCompact 重算视图下完整物理边并集的资源需求。该路径改变候选范围，消融中归入 A3。FLUTE、初解网顺序、动态价格及精确候选池入口沿用 V3。

## 档案及安全支配

CandidateArchive 保存不可变完整树、PreparedRoute 摘要、生成阶段、操作和阻塞关联。已提交路线独立保存，始终作为候选零号。旧 alternatives 在首次访问时导入。未取得单网改善而静态合法的候选可保留。静态检查覆盖自身容量、固定站点、HBT 内部间距与固定邻站。动态可提交性另查账本，资源变化后重新验证。

等价去重比较根点与物理边全集。同一线网的两棵静态合法完整树 \(A,B\) 满足 \(c(A)\le c(B)\)、所有 \(D_r(A)\le D_r(B)\) 和 HBT 站点集合 \(S_A\subseteq S_B\) 时，替换不会增加逐资源需求、站点冲突或预算用量。固定归属和真实端点由两棵树自身满足。按已建模的需求单调、站点冲突约束，该替换保留 \(B\) 的可行组合及其目标上界。需求比较采用原浮点值，无放宽容差。此保证针对同一个完整候选选择问题。

每网最多 8 个替代候选，全局载荷上限估算为 64 MiB。优先保留代价、HBT、线长和 Via 各自最小者，随后考虑资源交换关系与不同 HBT 站点集合。容量淘汰单独计数，进程峰值 RSS 另外反映边集合分配器等开销。档案容量和两网邻域属于局部搜索限制。安全支配只作用于完整树。

## 动态阻塞与原子事务

RoutingGraph::dynamicBlockers 区分请求资源及实际占用资源。Wire/Via 请求先查自身容量，再查外部占用。HBT 记录同站点或最小间距冲突。永久非法资源不触发交换。users 从反向索引找拥有者。协调器以真实关系新增两网任务，并复用原有更大冲突组。只有已完整求解，而且全局账本、线网及档案版本均一致，才跳过相同任务。使用全局版本失效可能增加重求次数。

groupView 仅扣除组内旧占用，保留组外需求及固定规则。组再生成复用 refineTopology 和 SparseMaze::candidates。预算组从现有档案按实际 HBT 差值分桶，在相反变化方向中有限选取实际固定目标可改善的伙伴。配对既考虑可行预算，也优先减少已有超额量。

selectGroup 复用 ConflictOptimizer 的深度优先搜索。canReplaceGroup 检查每个完成组合的累计资源和站点间距。剩余线网的最小代价与最少 HBT 给出安全下界。代价在与叶节点相同顺序下用扩展精度累加。严格改善比较阈值为 \(10^{-9}\)。完整枚举测试关闭下界但保留同一物理检查。最优性仅适用于当前有限候选池完整求解。

replaceJoint 检查参与线网版本及联合目标。replaceGroup 预检累计约束，准备所有者索引和新账本项，再发布差量。上层以交换物理边与更新已有摘要指针发布路线及版本。提交前失败或超时无改善时保留旧的完整物理树。

## 复杂度和可验证证据

单网档案容量为 \(K\) 时，去重与安全筛选各比较最多 \(K\) 份物理边或摘要。每次比较线性扫描排序边或资源，候选管理有 \(O(K\log K)\) 排序开销。阻塞记录扫描候选需求、HBT 邻站及资源拥有者。记录和任务队列皆设有明确工程上限。

设组内累计摘要总尺寸 \(R\)、HBT 站点数 \(H\)、被查邻站关系数 \(J\)。单个组合检查需要合并排序账本、查询剩余容量及检查站点，保守记为 \(O(R\log R+H\log H+J\log H)\)，另计稀疏视图查询。两网最坏 \(K_A K_B\) 次组合检查，多网是 \(\prod_i K_i\)。分支定界减少实际访问，另需每分支累加剩余最小代价。求解器维护当前组合和稀疏工作区，空间不随全部组合数量显式增长。

接受案例包含组外资源、阻塞者、实际树和单网顺序验证。scripts/final3d_exchange_check.py 从实测记录重新核算累计需求、站点冲突、固定代价及先后提交顺序。正式物理验证另外运行双裸片布线树回放及 OpenROAD/TritonRoute（详细布线器）与导体几何审计。
